# Проверка разбивки файла на PNG

Проверяется реализация плана `docs/superpowers/plans/2026-09-30-multipart-png.md`. Рабочий checkout: `/Users/Azat/.codex/worktrees/multipart-png/sendler`. Основной checkout сохранён без изменений реализации.

## Автоматические проверки

Среда: macOS, Node.js v25.2.1, встроенный Web Crypto. Команда: `node --test tests/*.test.js`.

Проверки покрывают расчёт обоих способов разбивки и граничных значений, дробный ввод, пустой файл, пакет v2 и AAD, независимые криптографические fixtures, уникальные IV и однократный вывод ключа, старый v1, порядок частей, пропуски, повторы, смешение наборов и версий, повреждение и пароль, точные байты сборки, ошибки создания PNG/URL/Blob, очистку всех ссылок, повторную попытку, блокировку элементов и отсутствие браузерных API. Отдельно проверен полный цикл из скриптов, встроенных в автономный HTML.

Тесты формы используют упрощённый DOM и тестовые Image/Canvas. Они выполняют настоящие модули криптографии и кодека, но не доказывают работу браузерного Canvas или визуальную доступность интерфейса.

## Дополнительные циклы настоящих PNG через ImageIO

Временный воспроизводимый скрипт `/private/tmp/sendler-png-verification/png-check.js` использует настоящие FileParts/VaultCore/ImageCodec, стандартную PNG-сериализацию через Node zlib и CRC, затем независимый системный декодер `sips` (macOS ImageIO) с чтением полученных BMP. Части восстанавливаются в обратном порядке; результаты сравниваются SHA-256 и `cmp`. Скрипт и большие образцы не добавлены в Git и не являются зависимостями приложения.

| 37 МиБ / размер 20 МиБ | 20971520 + 17825792 байт | SHA-256 совпал, cmp exit 0 | 2,30 с |

| Пустой файл | 0 байт, одна часть | SHA-256 совпал, cmp exit 0 | 0,15 с |
| Unicode-имя | 5 байт, одна часть | SHA-256 совпал, cmp exit 0 | 0,10 с |

SHA-256 исходного и обоих восстановленных файлов 37 МиБ: `60bdb37db89df30624b43e8e4af1a8631e3cd3c0aa39045c3f58a6926ff62110`.

SHA-256 исходного и восстановленного файла 512 МиБ: `fbeefe008d7ccc65988b48ec23f6786437377c0c8c86350ac3d5adef0de338db`.

PNG для частей 9,25 МиБ занимали примерно 11,06 млн байт каждый; PNG для части 64 МиБ — примерно 76,54 млн байт. Это подтверждает, что размер PNG отличается от заданного объёма данных. Точные результаты — `/private/tmp/sendler-png-verification/results.json`.

У тестового Mac 16 ГиБ RAM. Наибольший RSS Node, замеченный скриптом в сценарии 512 МиБ, — 1847607296 байт. Это измерение тестового CLI, который держит исходный буфер и системно перекодирует изображения; оно не является измерением браузера и не задаёт его гарантированный расход памяти.

## Неподтверждённые браузерные проверки

Первый доступ к Chrome был недоступен, Mac был заблокирован. После запроса пользователь разблокировал Mac. Встроенный Browser Use отклонил `file:` по политике URL и прямо запретил обход ограничения. Браузерная проверка не выполнена и не отмечается как пройденная.

Остаётся ручная проверка по README: открытие через file:, работа настоящего Canvas, скачивание и повторный выбор PNG, визуальная/клавиатурная доступность, узкое окно, скрытие в прозрачном носителе, поведение браузера с частями 64 МиБ и файлом 512 МиБ. Реальные PNG/ImageIO и модульные тесты не заменяют эти проверки. Согласованные пределы не изменены.
