# Разбивка файла на несколько PNG

Дата: 2026-09-30. Статус: дизайн согласован в обсуждении; документ подготовлен для проверки пользователем перед составлением плана реализации.

## Цель и согласованный объём

Пользователь может преобразовать большой файл в набор автоматически создаваемых PNG и восстановить исходный файл из полного набора с помощью одного пароля. Пример: файл 37 МиБ разделяется либо на указанное количество частей, либо на части с указанным объёмом исходных данных.

Согласовано:

- Разбивка применяется только к режиму «Создать PNG с данными».
- Пользователь задаёт количество частей или произвольный размер исходных данных в части, включая дробные значения и значения больше прежних 10 МиБ.
- Размер итогового PNG не ограничивается выбранным размером исходных данных: он включает шифрование, служебные данные и кодирование изображения.
- Результат — список отдельных PNG со ссылкой на каждый, без ZIP.
- Для восстановления пользователь выбирает все части одновременно и вводит общий пароль. Порядок выбора и имена PNG не определяют порядок сборки.
- Поддержка извлечения из ранее созданных одиночных PNG сохраняется.
- Стартовые защитные пределы: исходный файл до 512 МиБ включительно, данные одной части до 64 МиБ включительно, до 1000 частей включительно.
- Приложение остаётся локальным автономным `index.html`, без сервера, внешних библиотек и постоянного хранения данных.

Эти пределы ограничивают допустимые входы приложения, но не гарантируют наличие достаточной памяти на каждом устройстве. Пределы проверяются в браузере при реализации; невозможность обработки внутри них должна приводить к понятной ошибке, а не молчаливому изменению параметров.

В объём не входят: разбивка для режима «Скрыть в картинке», подбор нескольких носителей, ограничение размера готовых PNG, ZIP, частичное восстановление, дозагрузка частей между операциями, сохранение прогресса и работа с несколькими наборами за одну операцию.

## Текущая структура проекта

- `vault-core.js` реализует формат FVLT версии 1, PBKDF2 и AES-GCM. Сейчас весь исходный файл и расшифрованный файл ограничены 10 МиБ.
- `image-codec.js` записывает пакет в RGB-каналы автоматически создаваемого PNG или в младшие биты выбранного носителя; при извлечении возвращает байты пакета.
- `app.js` читает весь исходный файл через `arrayBuffer()`, создаёт один результат и извлекает из одного PNG.
- `index.template.html` и `styles.css` являются исходниками интерфейса. `scripts/build-standalone.js` встраивает их и JavaScript в переносимый `index.html`.
- Проверки модулей находятся в `tests/`; существующий тест переносимого HTML проверяет встраивание и цикл кодирования пакета.

## Пользовательский сценарий создания

В форме «Создать PNG с данными» добавить выбор способа упаковки:

1. **Один PNG** — выбран по умолчанию, создаёт одну часть. При превышении 64 МиБ предлагает выбрать разбивку.
2. **По количеству частей** — целое число частей.
3. **По размеру части** — положительное число и единица размера: КиБ или МиБ. Рядом объяснить единицы: 1 КиБ = 1024 байта, 1 МиБ = 1024 × 1024 байт. Это уточняет используемые сейчас двоичные величины, обозначенные в интерфейсе как КБ и МБ.

Ввод размера принимает точку или запятую как десятичный разделитель. Перевод в байты округляет вниз, чтобы заданный объём был верхним пределом. Значение, после округления меньше одного байта, недопустимо. Бесконечность, отрицательные значения и некорректная запись отклоняются; значение не исправляется автоматически.

До запуска показывать число частей, диапазон размеров их исходных данных и отдельно размер последней части для режима по размеру. Указывать, что это не размеры PNG. При недопустимых параметрах объяснять, как изменить их, и не начинать шифрование.

Примеры для исходного файла ровно 37 МиБ:

- 4 части: каждая по 9,25 МиБ.
- Размер части 10 МиБ: 10 + 10 + 10 + 7 МиБ.
- Размер части 20 МиБ: 20 + 17 МиБ.

Во время обработки показывать текущую часть и общее число частей. После успешного создания всего набора отображать список с именем, фактическим размером PNG и отдельной ссылкой скачивания каждого файла. Имена: `<основа>.part-001-of-004.png`; ширина номера не меньше трёх цифр, для 1000 частей — четыре. Для режима «Один PNG» допустимо сохранить существующее имя `<основа>-данные.png`.

## Точные правила разделения

Все вычисления размеров выполняются в целых байтах с проверкой `Number.isSafeInteger` после преобразования пользовательского ввода.

Для файла размера S и количества N:

- N — целое число от 1 до 1000.
- Если S > 0, N не может превышать S: пустые части не создаются.
- q = floor(S / N), r = S mod N.
- Первые r частей имеют размер q + 1, остальные — q. Разница размеров не превышает одного байта.
- Смещение части i, где нумерация начинается с нуля: i × q + min(i, r).
- Если максимальная часть больше 64 МиБ, отклонить настройку и предложить увеличить количество.

Для заданного размера C:

- C — целое число байт после преобразования, от 1 до 64 МиБ.
- Число частей для непустого файла: ceil(S / C).
- Часть i начинается с i × C и содержит min(C, S − i × C) байт.
- Если получится более 1000 частей, отклонить настройку и предложить увеличить размер части.
- Если C >= S, создаётся одна часть.

Пустой файл создаёт одну часть с нулевым содержимым и сохраняет имя и тип. В режиме по количеству для пустого файла допустимо только N = 1. Значение C проверяется и для пустого файла.

## Архитектура и границы компонентов

### `file-parts.js` — планирование и проверка набора

Новый модуль без DOM, Canvas и криптографии. Отвечает за защитные пределы, расчёт диапазонов байтов, проверку метаданных частей и построение порядка сборки. Принимает числа и записи метаданных; не читает файлов и не хранит паролей.

При проверке набора требует один идентификатор, совпадающие исходное имя, MIME-тип, общий размер и количество частей. Проверяет уникальность индексов, полноту диапазона индексов, непрерывность смещений без перекрытий и совпадение суммарного размера с объявленным размером файла. Не требует равенства размеров частей: правильность сборки определяется диапазонами и полнотой.

### `vault-core.js` — версия 2 и совместимость

Сохранить существующие функции версии 1 для режима скрытия и чтения старых PNG. Добавить отдельный путь создания частей версии 2 и распознавание версии при расшифровании. Старый предел 10 МиБ остаётся частью правил версии 1; новый путь имеет свои согласованные пределы.

Для новой операции создаётся случайная 16-байтовая соль и ключ AES-GCM 256 через существующий PBKDF2 SHA-256 с 310000 итерациями. Ключ выводится один раз на набор и используется только в рамках операции. Все части используют эту соль, но разные случайные 12-байтовые IV. При создании проверять уникальность IV в наборе, при случайном совпадении генерировать новый.

### `app.js` — последовательная обработка и интерфейс

Создание: проверка ввода → план диапазонов → получение ключа → для каждого диапазона `File.slice()` и `arrayBuffer()` → шифрование части → кодирование в пиксели → PNG Blob → накопление готовых PNG → показ списка.

Извлечение: выбор файлов → поочерёдная проверка PNG и декодирование пакетов → расшифрование → проверка метаданных → проверка полного набора → упорядочивание → `Blob` из данных частей → одна ссылка на исходный файл.

Ключ при извлечении можно повторно использовать для частей с той же солью в рамках операции. Принадлежность набору определяется защищёнными метаданными после расшифрования; совпадения соли недостаточно. Нельзя смешивать версии 1 и 2 или несколько отдельных пакетов версии 1 в одной операции. Один выбранный пакет версии 1 обрабатывается существующим способом.

### Изображения и переносимая сборка

Формат RGB-контейнера VDAT и `image-codec.js` не требуют изменения для передачи частей: кодек продолжает работать с произвольным пакетом байтов. Ограничения размеров изображения сохраняются.

Добавить `file-parts.js` в шаблон и скрипт встраивания, до `app.js`. Проверка переносимого HTML должна учитывать новый модуль и проверять цикл восстановления набора из встроенных модулей. Весь результат по-прежнему передаётся одним `index.html`.

## Формат FVLT версии 2

Внешний заголовок сохраняет структуру версии 1: сигнатура FVLT (4 байта), версия (1 байт, значение 2), длина шифротекста (uint32), соль (16 байт), IV (12 байт). Всего 37 байт. Многобайтовые числа записываются big-endian, как в существующем формате.

Для версии 2 все 37 байт внешнего заголовка передаются AES-GCM как additional authenticated data. Длина шифротекста известна заранее: длина открытого содержимого плюс 16-байтовый тег. Версия 1 расшифровывается по прежним правилам без этого дополнительного параметра.

Открытое содержимое перед шифрованием имеет фиксированный 40-байтовый заголовок:

| Смещение | Поле | Размер |
| --- | --- | --- |
| 0 | Длина имени в UTF-8 | uint16 |
| 2 | Длина MIME-типа в UTF-8 | uint16 |
| 4 | Длина данных этой части | uint32 |
| 8 | Случайный идентификатор набора | 16 байт |
| 24 | Индекс части, начиная с 0 | uint32 |
| 28 | Количество частей | uint32 |
| 32 | Размер исходного файла | uint32 |
| 36 | Смещение данных в исходном файле | uint32 |

Далее идут имя в UTF-8, MIME-тип в UTF-8 и данные части. Имя и тип имеют прежний предел 65535 байт каждый. Выбранные пределы файлов помещаются в uint32; увеличение поддерживаемого размера за пределы uint32 потребует новой версии формата.

Идентификатор набора генерируется один раз на создание, независимо от имени и содержимого файла. Все поля заголовка содержимого, имя, тип и данные защищены AES-GCM. До расшифрования проверяются структура внешнего заголовка, соответствие объявленной длины фактической и верхний предел длины пакета: 37 + 40 + 65535 + 65535 + 64 МиБ + 16 байт. При расшифровании проверяются точная длина содержимого, корректность UTF-8, диапазоны индекса и размеров, а также `offset + length <= totalSize`. Нулевая длина допустима только для единственной части пустого файла.

Все новые PNG режима «Создать PNG с данными», включая одиночные, используют версию 2. Обновлённое приложение читает версии 1 и 2. Предыдущая версия приложения не сможет открыть новые пакеты версии 2; это объяснить в README. Режим «Скрыть в картинке» продолжает создавать версию 1 с существующим пределом.

## Восстановление и ошибки

Поле выбора PNG допускает несколько файлов. Пользователь должен выбирать полный набор в одной операции. До шифрования или извлечения проверяются параметры и количество выбранных файлов; одного пароля достаточно для всего набора.

Различать следующие ошибки:

- Неверные параметры разбивки или превышение защитных пределов — показать причину до обработки.
- Отсутствующие части — перечислить недостающие номера с нумерацией от 1.
- Повтор части — сообщить повторный номер, не отбрасывать его молча.
- Части разных наборов или несовместимые сведения об исходном файле — отказаться от сборки.
- Неверный пароль или повреждённый пакет — сохранить существующее объединённое сообщение, не обещать отличить эти причины.
- Неподдерживаемая версия, не-PNG, неверная структура или диапазоны — понятная ошибка без ссылки на восстановленный файл.
- Ошибка Canvas, выделения памяти или создания Blob — завершить операцию, очистить подготовленные результаты и предложить уменьшить объём обработки. Не публиковать неполный набор.

Ограничения и структуру отдельных расшифрованных частей проверять сразу, не откладывая до накопления всего набора. Имена для скачивания исходного файла очищать существующим способом от компонентов пути.

## Жизненный цикл результатов и память

Порционная обработка уменьшает временные массивы при создании и число одновременно декодированных изображений при извлечении. Она не делает весь процесс потоковым до диска: готовые PNG Blob занимают память до завершения работы с результатом, а восстановление накапливает данные частей для итогового Blob.

При сборке не создавать дополнительный массив размера всего файла; передавать упорядоченные массивы частей непосредственно в `new Blob(...)`. Это не является гарантией отсутствия копирования внутри браузера.

После каждой части освобождать ссылки на временные пиксельные массивы, пакеты и Canvas. При смене исходного файла, пароля, способа разбивки, параметров или режима, а также перед новой операцией удалять результаты и отзывать все их Object URL. При закрытии страницы также отзывать URL. В обработке сохраняется существующая блокировка повторного запуска и изменения входов.

## Проверка при реализации

1. Расчёт по числу и размеру: деление с остатком, ровное деление, произвольные значения больше 10 МиБ, дробные значения, точка и запятая, единицы, округление до байта, одна часть и пустой файл.
2. Границы: ровно 512 МиБ, 64 МиБ и 1000 частей; превышение каждого предела; нулевые, отрицательные и нецелые количества; слишком маленькая часть; количество больше числа байтов. Большие размеры для расчётов проверять без выделения соответствующих массивов.
3. Формат версии 2: полный цикл шифрования, имена UTF-8, точные длины пакетов, защищённые метаданные и внешний заголовок, неверный пароль, повреждение и неверная структура.
4. Полный набор: перемешанный порядок, переименованные PNG, пропуск, повтор, смешение разных наборов и версий, разрыв и перекрытие диапазонов, несовпадение размера или имени. Никакие невалидные наборы не возвращают готовый файл.
5. Совместимость: существующая фиксированная тестовая запись версии 1, одиночные PNG обоих прежних режимов, сохранение предела и поведения режима скрытия.
6. Автономная сборка: встроенные модули нового `index.html` восстанавливают набор без внешних CSS, JS или сети.
7. Проверка в браузере скачанных PNG: файл ровно 37 МиБ → 4 равные части; тот же файл → части по 20 МиБ; восстановление побайтно и с исходным именем и типом. Дополнительно проверить все ссылки, фактические размеры PNG, ошибки набора и удаление старых результатов после изменения настроек.
8. Ресурсы в браузере: измерить поведение на частях 64 МиБ и больших наборах вплоть до согласованного предела на доступном тестовом устройстве. Зафиксировать среду и результат; успешные проверки на одном устройстве не переносить на все браузеры и устройства. Если защитные пределы нужно изменить, согласовать изменение до завершения реализации.

## Дальнейший шаг

После проверки пользователем этого документа составить отдельный план реализации с конкретными файлами, тестами и порядком изменений. Реализацию до согласования плана не начинать.
